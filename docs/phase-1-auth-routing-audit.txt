# Phase 1: Diagnose and Fix Backend, Authentication & Routing Integration Audit Report

## 1. Executive Summary & Root Cause Analysis

### A. Root Causes of Routing Failure
1. **Unregistered Admin Portals in Route Hierarchy**:
   - The route descriptors for SuperAdmin (`superadmin.routes.jsx`), Non-Tech Admin (`nontechadmin.routes.jsx`), and Tech Admin (`techadmin.routes.jsx`) and their respective layouts (`SuperAdminLayout.jsx`, `NtaLayout.jsx`, `TechAdminLayout.jsx`) were drafted in working tree but:
     - `techadmin.routes.jsx` only registered `dashboard`. The user requested tickets route (`/tech-admin/tickets`) was not registered, and `frontend/src/pages/TechAdmin/tickets.jsx` was an empty 0-byte stub file rather than mounting `TicketList.jsx`.
2. **Missing `/unauthorized` Route & Flawed Unauthenticated Redirection**:
   - In `frontend/src/routes/ProtectedRoutes.jsx`, if `!allowedRoles.includes(user.role)`, it redirected to `/unauthorized`.
   - However, when a visitor is unauthenticated, `user.role` is `'default'`. Because `'default'` is not in `allowedRoles`, the guard redirected unauthenticated visitors to `/unauthorized`.
   - Crucially, no route for `/unauthorized` existed in `App.jsx`, causing a blank screen/unmatched route when navigating directly to any protected portal while logged out.
   - Guard must distinguish unauthenticated (`!user || user.role === 'default'`) -> redirect to `/Auth/login`, from authenticated but unauthorized (`allowedRoles` does not match `user.role`) -> redirect to `/unauthorized` (with an actual Unauthorized error component displayed).

### B. Root Causes of Backend Startup & Authentication Failures
1. **Backend Dependencies Missing**:
   - `backend/node_modules` was missing completely (`Test-Path backend\node_modules` returned `False`). Running `npm run start` in `backend` failed with 198 TypeScript errors (`Cannot find module '@nestjs/common'`, etc.).
   - Running `npm install` in `backend` is required to restore NestJS framework and TypeScript compilation.
2. **Global Prefix vs Endpoint Harmonization**:
   - Backend `backend/src/main.ts` configures `app.setGlobalPrefix('api')`.
   - Thus, all backend endpoints are hosted at `http://localhost:3000/api/...`.
     - Auth: `/api/auth/login`, `/api/auth/register`, `/api/auth/users`
     - Tickets: `/api/tickets`
     - Plans: `/api/plans`
     - Trips: `/api/trips`
     - Guide Requests: `/api/guide-requests`
   - Services like `tickets.api.js`, `plans.api.js`, `superadmin.api.js`, `nta.api.js` had `const BASE_URL = import.meta.env.VITE_BACKEND_URL || 'http://localhost:3000'` without `/api`. Calling `${BASE_URL}/tickets` reached `http://localhost:3000/tickets` (404 Not Found), whereas the NestJS backend was listening at `http://localhost:3000/api/tickets`.
   - Standardizing `BASE_URL` to `http://localhost:3000/api` ensures live API calls resolve against NestJS endpoints.
3. **Login Destination Mapping & Session Sync**:
   - In `frontend/src/pages/Auth/login.jsx`, `submitHandler` writes directly to `localStorage.getItem('xploreoUser')` and calls `onAuthenticated?.(result.user)`.
   - Destination mapping in `login.jsx`:
     - `superadmin`: `/superadmin/dashboard`
     - `nontechadmin`: `/nta/dashboard`
     - `techadmin`: `/tech-admin/dashboard`
     - `guide`: `/guide/dashboard`
     - `hotel`: `/hotel/dashboard`
     - `experience`: `/experience/home`
     - `traveller`: `/`
   - Verified backend role enum (`backend/src/contracts/api-contracts.ts`):
     - `superadmin`, `traveller`, `guide`, `techadmin`, `nontechadmin`, `hotel`, `experience`.
     - The role strings match 1:1.
4. **Shared Navbar Integration**:
   - `frontend/src/components/Navbar/navbar.jsx` only displays static links and when signed in, shows `user.name` without a link to their dashboard or any logout action.
   - Needs portal dashboard link and a logout button that calls `useAuth().logout()` to clear session and return to guest state.

## 2. Intended Changes & Affected Files

1. **Backend Environment & Dependencies**:
   - Run `npm install` in `backend/` using exact lockfile (`package-lock.json`).
   - Development command: `npm run start:dev` (or `npm run start`).

2. **Frontend `ProtectedRoutes.jsx` & Unauthorized View**:
   - File: `frontend/src/routes/ProtectedRoutes.jsx`
   - Fix: Check if user is authenticated (`user && user.role && user.role !== 'default'`). If not, redirect to `/Auth/login` with `replace state={{ from: location }}`.
   - If authenticated and not in `allowedRoles`, redirect to `/unauthorized`.
   - Create `frontend/src/pages/Unauthorized.jsx` with a clean, branded UI explaining insufficient permissions and a link to return to the appropriate portal or home.
   - File: `frontend/src/App.jsx`: Register `/unauthorized` route.

3. **TechAdmin Tickets Page Mount**:
   - File: `frontend/src/pages/TechAdmin/tickets.jsx`
   - Mount `TicketList.jsx`, wire `getTickets` and `resolveTicket` from `tickets.api.js` using the authenticated session from `useAuth()`.
   - File: `frontend/src/routes/techadmin.routes.jsx`: Add `{ path: 'tickets', element: <TechAdminTickets /> }`.
   - File: `frontend/src/components/techadmin/TechAdminLayout.jsx`: Add Tickets link `{ to: '/tech-admin/tickets', label: 'Ticket Queue', icon: 'support.svg' }`.

4. **Harmonize API Client URLs**:
   - Files:
     - `frontend/src/services/api.js`: Provide shared base URL default `http://localhost:3000/api`.
     - `frontend/src/services/tickets.api.js`: Default `BASE_URL = import.meta.env.VITE_BACKEND_URL || 'http://localhost:3000/api'`.
     - `frontend/src/services/superadmin.api.js`: Default `BASE_URL = import.meta.env.VITE_BACKEND_URL || 'http://localhost:3000/api'`.
     - `frontend/src/services/nta.api.js`: Default `BASE_URL = import.meta.env.VITE_BACKEND_URL || 'http://localhost:3000/api'`.
     - `frontend/src/services/plans.api.js`: Default `BASE_URL = import.meta.env.VITE_BACKEND_URL || 'http://localhost:3000/api'`.

5. **Login Destination Mapping & Navbar Role Awareness**:
   - File: `frontend/src/pages/Auth/login.jsx`: Ensure destination mapping includes `traveller: "/"` and all admin portals.
   - File: `frontend/src/components/Navbar/navbar.jsx`:
     - Display a role-specific dashboard link (e.g. "Admin Dashboard", "Guide Portal", etc.) based on `user.role`.
     - Add a "Log out" button that clears session and navigates home.

   - Start backend (`npm run start:dev` or `npm run start`) and confirm listening on `http://localhost:3000/api`.
   - Send `POST /api/auth/login` with seeded credentials:

     - NonTechAdmin: `NTA001` / `NTA@123`

   - Log in as `TA001` -> verify redirected to `/tech-admin/dashboard`.

   - Direct visit to `/nta/dashboard` while logged in as `NTA001` -> verify dashboard renders.
   - Click "Log out" -> verify session cleared, redirected to home, protected routes inaccessible.

3. **Build & Lint Verification**:
