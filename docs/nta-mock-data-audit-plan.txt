================================================================================
XPLOREO NTA MOCK DATA AUDIT PLAN
================================================================================

1. OBJECTIVES & SCOPE
---------------------
The objective is to audit where mock data originates in the Xploreo React application,
inspect the actual source code across NTA Manage Plans and NTA Guide Applications,
and assess data flow, authorization boundaries, fallback behaviors, and cross-actor
rules across all 5 supported regions:
  - Jaipur
  - Goa
  - Delhi
  - Mumbai
  - Kerala

The audit covers:
- Module 1: NTA Manage Plans (PlanList, PlanForm, plans.api.js, seeds/plans.json)
- Module 2: NTA Guide Applications (GuidesPage, nta.api.js, nta_metrics.json, guide-requests)
- Cross-Actor & Cross-Region Boundaries: NTA (regional isolation), SuperAdmin (global access),
  Guide, Traveler, Experience Partner, Hotel Partner.

2. TARGET ARTIFACTS AND SOURCE FILES
------------------------------------
A. Frontend Components & Pages:
   - frontend/src/pages/NonTechAdmin/plans.jsx (NTA Plans management page)
   - frontend/src/pages/NonTechAdmin/guides.jsx (NTA Guide applications review page)
   - frontend/src/pages/NonTechAdmin/dashboard.jsx (NTA Telemetry dashboard)
   - frontend/src/components/nta/PlanList.jsx (Plans list view, region pill filter, search)
   - frontend/src/components/nta/PlanForm.jsx (Plan create/edit form, region locking)
   - frontend/src/components/nta/NtaLayout.jsx (NTA portal layout and navigation)
   - frontend/src/routes/nontechadmin.routes.jsx (NTA route definitions)

B. Frontend Services & Fixtures:
   - frontend/src/services/plans.api.js (getPlans, getPlanById, createPlan, updatePlan, deletePlan)
   - frontend/src/services/nta.api.js (getGuideApplications, updateGuideApplicationStatus, dashboard metrics)
   - frontend/src/services/session.js (Session storage, token extraction, identity headers)
   - frontend/src/context/AuthContext.jsx (Auth state, token decoding, user normalization)
   - frontend/src/mocks/plans/plans.fixture.js (MOCK_PLANS canonical export)
   - frontend/src/mocks/plans/hotels.fixture.js (MOCK_HOTELS_CATALOG canonical export)
   - frontend/src/mocks/plans/experiences.fixture.js (MOCK_EXPERIENCES_CATALOG canonical export)
   - frontend/src/mocks/nta/nta.fixture.js (DEMO_GUIDE_APPLICATIONS and NTA metrics)
   - Database/seeds/plans.json (Canonical root seed for plans)
   - Database/fixtures/admin/nta_metrics.json (Canonical root fixture for NTA domain)
   - Database/fixtures/hotels/catalog.json (Canonical partner hotels)
   - Database/fixtures/experiences/catalog.json (Canonical curated experiences)

C. Backend Contracts & Validation:
   - backend/src/plans/plans.controller.ts
   - backend/src/plans/plans.service.ts
   - backend/src/plans/plans.repository.ts
   - backend/src/plans/dto/create-plan.dto.ts
   - backend/src/plans/dto/update-plan.dto.ts
   - backend/src/guide-requests/guide-requests.controller.ts
   - backend/src/guide-requests/guide-requests.service.ts
   - backend/src/guide-requests/guide-requests.repository.ts
   - backend/src/auth/auth.repository.ts (Seed users: NTA001 with region 'Jaipur')

3. AUDIT INSPECTION CRITERIA
----------------------------
1. Fixtures & Datasets:
   - Check coverage of all 5 regions (Jaipur, Goa, Delhi, Mumbai, Kerala) in plans.json and nta_metrics.json.
   - Verify hotel and experience ID alignment with catalog.json files.
2. Services & Fallbacks:
   - Inspect mock-mode toggling (isPlansMockMode, isNtaMockMode, VITE_MOCKS).
   - Check where in-memory state is maintained (localMockStore, ntaMockStore).
   - Check behavior when backend is running vs when fallback/mock mode is active.
3. Identity & Regional Authorization:
   - Determine how activeUser / session is resolved in PlansPage, GuidesPage, and DashboardPage.
   - Check whether client props override or fallback to authenticated session.
   - Inspect backend enforcement in PlansService and GuideRequestsService.
4. Mutation & Persistence:
   - Determine how create, edit, delete, accept, reject actions persist in mock mode vs live mode.
   - Note limitations (e.g. guide rejection reasons persistence in backend vs mock store).
5. Existing Test Coverage:
   - Verify backend unit/integration tests (src/auth/auth-security.spec.ts).
   - Run tests to record verified results vs source-inspection deductions.
