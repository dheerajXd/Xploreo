1. DIAGNOSIS & ROOT CAUSE IDENTIFICATION
--------------------------------------------------------------------------------
Investigation traced the login flow across:
- `Database/seeds/users.json`
- `backend/src/auth/auth.repository.ts`
- `backend/src/auth/auth.service.ts`
- Active running backend process (PID 13952 on port 3000)
- `frontend/src/services/session.js` & `AuthContext.jsx`

Findings:
1. Data Sources Verified:
   - Both `Database/seeds/users.json` and `backend/src/auth/auth.repository.ts`
     contained all 5 NTA accounts with their respective regions:
     * NTA001 -> Jaipur
     * NTA002 -> Goa
     * NTA003 -> Delhi
     * NTA004 -> Mumbai
     * NTA005 -> Kerala
2. Exact Failure Identified:
   - The backend server running on port 3000 was started previously (PID 13952)
     before NTA002–NTA005 were added to the codebase.
   - Because `AuthRepository` initializes its in-memory user list upon application
     bootstrap (`loadSeedData<Auth>('users.json')`), the running process held stale
     in-memory user records containing only NTA001.
   - Any login attempt to NTA002–NTA005 against port 3000 failed with HTTP 401
     ("Invalid username or password") because the stale server process could not
     locate the usernames in memory.
3. Stale Session Risk in Frontend:
   - In `frontend/src/services/session.js`, `clearUser()` removed `xploreoUser`
     and `currentUser` from localStorage, but did not clear `xploreoToken`,
     leaving the possibility of stale token reuse across consecutive logins.

2. IMPLEMENTED FIXES
--------------------------------------------------------------------------------
1. Server Process Refresh:
   - Terminated the stale running backend process (PID 13952).
   - Rebuilt the NestJS backend bundle (`npm run build`).
   - Relaunched the NestJS server using the updated seed and fallback definitions.
2. Frontend Session Hardening (`frontend/src/services/session.js`):
   - Updated `clearUser()` to explicitly remove `xploreoToken` alongside
     `xploreoUser` and `currentUser`, guaranteeing complete session cleanup upon
     logout or account transition.
3. AuthContext Normalization (`frontend/src/context/AuthContext.jsx`):
   - Ensured canonical region mappings for NTA001 (Jaipur), NTA002 (Goa),
     NTA003 (Delhi), NTA004 (Mumbai), NTA005 (Kerala), with server-signed JWT
     claims taking precedence over client parameters.
