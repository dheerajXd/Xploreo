[2.1 Existing Route Descriptor Pattern]
Audited existing portals:

- `frontend/src/routes/hotel.routes.jsx`
- `frontend/src/routes/experience.routes.jsx`

Common descriptor structure:
export const <role>Portal = {
  basePath: '/<role-prefix>',
  layout: <RoleLayout>,
  requires: { role: '<role-name>' },
  homePath: '/<role-prefix>/dashboard',
  routes: [
    { index: true, element: <Navigate to="dashboard" replace /> },
    { path: 'dashboard', element: <DashboardComponent /> },
    ...
  ],
};

Registration in `App.jsx`:
<Route element={<ProtectedRoute allowedRoles={["<role>"]} user={user} />}>
  <Route path={<portal>.basePath} element={<<portal>.layout />}>
    {<portal>.routes.map((route) => (
      <Route key={route.path ?? "index"} {...route} />
    ))}
  </Route>
</Route>

3. Planned Route Mapping & Descriptor Architecture
--------------------------------------------------------------------------------

[3.1 SuperAdmin Portal Descriptor]
- File: `frontend/src/routes/superadmin.routes.jsx`
- Base Path: `/superadmin`
- Home Path: `/superadmin/dashboard`
- Allowed Role: `['superadmin']`
- Layout: `SuperAdminLayout` (nav links for Dashboard, Users, Finance, Operations)
- Registered Routes:
  1. `/superadmin` (index) -> Redirects to `dashboard`
  2. `/superadmin/dashboard` -> `SuperAdminDashboardPage` (`SuperAdmin/dashboard.jsx`)
  3. `/superadmin/users` -> `SuperAdminUsersPage` (`SuperAdmin/users.jsx`)
  4. `/superadmin/finance` -> `SuperAdminFinancePage` (`SuperAdmin/finance.jsx`)
  5. `/superadmin/operations` -> `SuperAdminOpsBookPage` (`SuperAdmin/opsbook.jsx`)

[3.2 Non-Tech Admin Portal Descriptor]
- File: `frontend/src/routes/nontechadmin.routes.jsx`
- Base Path: `/nta`
- Home Path: `/nta/dashboard`
- Allowed Role: `['nontechadmin']`
- Layout: `NtaLayout` (nav links for Dashboard, Packages, Guide Applications)
- Registered Routes:
  1. `/nta` (index) -> Redirects to `dashboard`
  2. `/nta/dashboard` -> `NtaDashboardPage` (`NonTechAdmin/dashboard.jsx`)
  3. `/nta/plans` -> `PlansPage` (`NonTechAdmin/plans.jsx`)

4. Layout Components Strategy
--------------------------------------------------------------------------------
To match the established portal layout convention (`GuideLayout`, `HotelLayout`, `ExperienceLayout`),
we will create clean portal layout wrappers:
1. `frontend/src/components/superadmin/SuperAdminLayout.jsx`
   - Renders `Navbar` with SuperAdmin portal links (`Dashboard`, `Users`, `Finance`, `Operations`), user identity, and logout.
   - Renders `<Outlet />` for child routes.
2. `frontend/src/components/nta/NtaLayout.jsx`
   - Renders `Navbar` with NTA portal links (`Dashboard`, `Manage Packages`, `Guide Applications`), user identity with assigned region, and logout.
   - Renders `<Outlet />` for child routes.
3. `frontend/src/components/techadmin/TechAdminLayout.jsx`
   - Renders `Navbar` with TechAdmin portal links (`Support Dashboard`), user identity, and logout.
   - Renders `<Outlet />` for child routes.
