1. OBJECTIVE & SCOPE
--------------------------------------------------------------------------------
Phase 4B implements targeted, minimal, non-disruptive security fixes addressing
the highest-priority vulnerabilities identified in the Phase 4A audit:

Priority 1: Cryptographic Authentication Architecture
- Replace client-trusted identity headers (`x-user-role`, `x-user-id`) with verified
  signed JWT authentication while strictly preserving existing login behavior across
  all seven actor roles.
- Never trust a client-supplied role, user ID, or region as proof of identity.

Priority 2: Trip Ownership and Profile Privacy
- Prevent travelers from reading or enumerating other travelers' trips via
  `GET /trips/:id` and `GET /trips/traveller/:travellerId`.
- Permit access only to the trip owner, assigned guide, or authorized admin roles.
- Restrict traveler and guide profile responses (`GET /traveller/:id`, `GET /guide/:id`)
  to authorized callers and prevent leaking private contact information (phone, email,
  bank account/IBAN) to third parties.

Priority 3: Non-Tech Admin (NTA) Regional Isolation
- Resolve the authenticated NTA's assigned region from server-side trusted state
  (via `AuthRepository` / `NontechadminRepository`).
- Enforce region restrictions in backend `PlansService` (`findAll`, `create`, `update`)
  and `TripsService` (`findAll`, `create`, `update`).
- Prevent query parameter manipulation (`?destination=...`) or foreign ID tampering
  from bypassing regional isolation.
- Preserve SuperAdmin's global access.

2. ARCHITECTURAL DESIGN & MIGRATION STRATEGY
--------------------------------------------------------------------------------

A. Authentication Migration Strategy (Priority 1)
- Current State:
  Frontend `session.js:identityHeaders()` sends:
    `x-user-role: role`
    `x-user-id: userId`
    `x-user-location: location`
  Backend `AuthGuard` in `backend/src/common/guards/auth.guard.ts` trusts these raw headers.
- Migration Design:
  1. Leverage `jsonwebtoken` (already installed in `backend/package.json` v9.0.3).
  2. In `backend/src/auth/auth.service.ts`:
     - Upon successful `POST /auth/login`, generate a signed JWT:
       `jwt.sign({ userId, username, role, region }, JWT_SECRET, { expiresIn: '7d' })`
     - Return `{ message, user, token, headers }` (maintaining backward compatibility).
  3. In `backend/src/common/guards/auth.guard.ts`:
     - Inspect `Authorization: Bearer <token>` or `x-access-token` or cookie/header.
     - Verify signature against `JWT_SECRET`.
     - Decode claims `{ userId, role, region }` directly from verified token.
     - Fallback / Transitional Behavior: If no Bearer token is provided, verify whether
       we allow header-based fallback only in development/test, or strictly reject unverified
       claims. Per prompt: "Never trust a client-supplied role, user ID, or region as proof of identity."
       Therefore, requests missing a valid signed token will be rejected with HTTP 401 Unauthorized
       (except public endpoints marked with `@Public()`).
  4. In `frontend/src/services/session.js`:
     - Store token alongside user in `localStorage.setItem('xploreoToken', token)` or inside `xploreoUser`.
     - Include `Authorization: Bearer <token>` in `identityHeaders()`.
     - Both `api.js` and `request.js` automatically propagate `identityHeaders()`.

B. Trip Ownership & Privacy Strategy (Priority 2)
- In `backend/src/trips/trips.controller.ts`:
  - Pass `req.user` to `findOne(id, req.user)` and `findByTraveller(travellerId, req.user)`.
- In `backend/src/trips/trips.service.ts`:
  - `findOne(id, actor)`:
    - If `actor.role === Role.TRAVELLER`, verify `trip.travellerId === actor.userId`.
    - If `actor.role === Role.GUIDE`, verify `trip.guideId === actor.userId`.
    - If `actor.role === Role.NONTECHADMIN`, verify trip's destination matches NTA's server-assigned region.
    - If `actor.role === Role.SUPERADMIN`, permit.
    - Otherwise throw `ForbiddenException('You are not authorized to view this trip.')`.
  - `findByTraveller(travellerId, actor)`:
    - If `actor.role === Role.TRAVELLER`, verify `travellerId === actor.userId`.
    - If admin, permit.
    - Otherwise throw `ForbiddenException('You can only view your own trips.')`.
- In `backend/src/traveller/traveller.controller.ts` & `service.ts`:
  - `findOne(id, actor)`:
    - If caller is traveler themselves (`actor.userId === id`) or Admin, return full profile.
    - If caller is another user (e.g., guide assigned to their trip), return sanitized profile (omit phone and email).
- In `backend/src/guide/guide.controller.ts` & `service.ts`:
  - `findOne(id, actor)`:
    - If caller is guide themselves or Admin, return full profile including financial details (`bank_name`, `iban`).
    - If caller is a traveler or public caller, sanitize and omit private banking fields (`iban`, `bank_acc_num_end`, `bank_name`, `email`, `phone`).

C. NTA Regional Isolation Strategy (Priority 3)
- In `backend/src/auth/auth.repository.ts`:
  - Ensure seed NTA user has `region: 'Jaipur'` (or matches `location`).
  - Add helper `findRegionForUser(userId: string): string | undefined`.
- In `backend/src/plans/plans.service.ts`:
  - In `findAll(query, actor)`:
    - If `actor.role === Role.NONTECHADMIN`, look up NTA's server-assigned region.
    - Enforce `query.destination = ntaRegion`, ignoring any caller-supplied destination override.
  - In `create(dto, actor)`:
    - If `actor.role === Role.NONTECHADMIN`, verify `dto.destination.toLowerCase() === ntaRegion.toLowerCase()`. Throw 403 Forbidden otherwise.
  - In `update(id, dto, actor)`:
    - If `actor.role === Role.NONTECHADMIN`, verify existing plan's `destination.toLowerCase() === ntaRegion.toLowerCase()`. Throw 403 Forbidden otherwise.
  - Preserve SuperAdmin global access.
- In `backend/src/trips/trips.service.ts`:
  - In `findAll(actor)`:
    - If `actor.role === Role.NONTECHADMIN`, filter returned trips to those where `trip.itinerary?.day1?.transport?.pickupLocation` or plan destination matches `ntaRegion`.
    - SuperAdmin sees all.
