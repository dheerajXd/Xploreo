4. HOW ACCOUNT SUSPENSION AFFECTS LOGIN AND EXISTING SESSIONS
--------------------------------------------------------------------------------
- Login Enforcement:
  * In `AuthService.login()`, when user credentials match, `user.status` is checked.
    If `user.status === 'inactive'`, login is immediately rejected with HTTP 401:
    "Account has been restricted. Please contact support."
- Active Session Invalidation:
  * In `AuthGuard.canActivate()`, upon verifying the signed JWT bearer token,
    `authRepository.findById(decoded.userId)` is checked.
    If `liveUser.status === 'inactive'`, the request is immediately rejected with
    HTTP 401: "Account has been restricted. Please contact support."
  * This guarantees that existing sessions, cached tokens, and active browser windows
    cannot continue executing API calls once an account is suspended.
- Reactivation:
  * Sets `status = 'active'` and clears suspension audit flags.
  * Restores login capability and allows newly issued or existing unexpired tokens
    to access protected endpoints.
