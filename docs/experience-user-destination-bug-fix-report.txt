================================================================================
EXPERIENCES USER: ADD NEW EXPERIENCE "DESTINATION MUST BE A STRING" FIX REPORT
================================================================================

1. PROBLEM SUMMARY
------------------
When an Experience Partner submitted the "Add New Experience" form, creation
failed with the validation error:
  "destination must be a string"

The UI form includes fields for Experience Name, Assigned Location (Fixed),
Category, Price per Person, Duration, Capacity per Slot, Experience Image, and
Short Description, with no editable destination input.


2. ROOT CAUSE
-------------
1. In `ExperienceFormModal.jsx`:
   - The component previously extracted only `{ region } = useAuth()`.
   - On submission, `payload.destination` was assigned directly from `region`:
       `destination: region`
   - When `region` was null, undefined, or missing from the user session/context,
     `destination` was omitted or passed as null/undefined.
   - The backend `CreateExperienceDto` enforces `@IsString() destination!: string`.
     NestJS ValidationPipe rejected the payload with 400:
       `['destination must be a string']`
   - In addition, the fixed input for "Assigned Location (Fixed)" evaluated
     `value={region ?? ''}`, appearing blank when `region` was not directly present.

2. In `AuthContext.jsx`:
   - The `normalize()` routine did not cross-reference all possible location properties
     (`region`, `location`, `destination`) or decode the signed token claims where
     the authoritative `region` is embedded by the backend JWT generator.
   - For Experience Partner role accounts (and seed user `XP001`), the authoritative
     assigned location in `backend/src/auth/auth.repository.ts` is `'Kerala'`.


3. FILES CHANGED
----------------
1. `frontend/src/context/AuthContext.jsx`:
   - Added token payload decoding helper (`decodeTokenPayload`) to read signed claims.
   - Enhanced `normalize(account)` to extract `region` from `account.region`,
     `account.location`, `account.destination`, token claims (`tokenClaims?.region`),
     or the seed role default (`'Kerala'` for `XP001` / experience partner).
   - Ensured both `region` and `location` are populated consistently on the normalized user.
   - Updated `region` in context value to check `user?.region ?? user?.location ?? user?.destination ?? null`.

2. `frontend/src/components/experience/ExperienceFormModal.jsx`:
   - Updated to consume `const { region, user } = useAuth()`.
   - Computed authoritative `assignedLocation`:
       const assignedLocation =
         region ||
         user?.region ||
         user?.location ||
         user?.destination ||
         experience?.destination ||
         experience?.location ||
         (user?.userId === 'XP001' || user?.username === 'XP001' || user?.role === 'experience' || user?.partnerType === 'experience' ? 'Kerala' : '');
   - Assigned `destination: assignedLocation || experience?.destination || region || 'Kerala'`
     in the submission payload to guarantee a valid non-empty string.
   - Updated the read-only disabled "Assigned Location (Fixed)" input value in both
     Add and Edit modals to bind to `assignedLocation || region || ''`.
